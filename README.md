# douziguo-skill

一套通用的协作规范，以 Skill 的形式提供给 AI 编程助手使用。

## 它解决什么问题

在很多开发场景里，用户手里是权威源码，而 AI 助手只能读到一份镜像或快照（例如本地只读挂载目录 + 远程/交叉编译的工作流）。如果助手基于过期代码给出改动，就会出现行号对不上、反复返工、根因判断错误等问题。

本技能把这些年总结出的协作纪律固化下来，让 AI 助手按统一方式工作：**先同步再给码、给完整函数、少改头文件、一次一个目标、不知道就问**。它只规定协作方式与交付规范，不含任何具体项目、框架或领域知识，因此可复用于各类 C/C++ 等需要手工落地改动的工程。

## 适用时机

当出现以下任一情形时启用本技能：

- 助手需要基于用户侧最新源码给出改动，但自己读的是镜像、挂载或快照。
- 用户要求「先同步再给码」「给完整函数」「不要改片段」「不要生成文件」。
- 涉及编译昂贵的场景，需要控制改动面（少动头文件、一次一个目标）。
- 用户要求梳理汇报、书面材料，强调「外行看得懂」。

## 目录结构

```
douziguo-skill/
├── SKILL.md                          # 技能主文件：用途、适用判断、15 条铁律、标准工作流
└── references/                       # 按需加载的详细参考
    ├── sync-discipline.md            # 同步纪律：快照过时根因、指令写法、范围控制、只读镜像、复原
    ├── code-delivery.md              # 交付规范：完整函数、少改头文件、一次一目标、给码格式
    ├── decision-discipline.md        # 决策纪律：不知道就问、方向由用户定、多方案拍板、证据优先
    └── reporting-style.md            # 汇报口径：纯中文、外行可读、只写已交付、跨工作区汇总
```

`SKILL.md` 是入口，包含最高优先级的 15 条铁律和标准工作流；`references/` 下的文档是对应主题的完整细节，按需加载，不必一次全读。

## 核心铁律摘要

1. **先同步、后给码**——读代码或给改动前先给同步指令，等用户回复「同步完成」再重读最新副本。
2. **判断同步范围的依据是「本轮会不会读/改它」**，拿不准就按要改算，禁止拿「先定位」当借口先读旧快照。
3. **定位阶段只用粗粒度手段**，一旦要报行号就必须已同步过。
4. **同步指令要能直接粘贴执行**——单条、单行、无续行，末尾带 md5/stat 校验。
5. **同步范围最小化**，默认只同步本轮关键文件。
6. **镜像目录只读**，绝不写入或编辑。
7. **给完整函数，不给片段**，落在函数里的改动整段重贴。
8. **少改头文件**，新增逻辑优先放进 .cpp 内部。
9. **一次只推进一个改动目标**。
10. **不擅自改 UI/界面描述文件**。
11. **不生成 md 交付文件**，代码直接贴在对话里。
12. **不知道就立刻问，禁止猜**。
13. **新增文件 ≠ 免同步**。
14. **给改动时同时给出上一轮的复原方式**。
15. **方向由用户定**，不擅自下钻到下层打补丁。

完整内容和案例见 `SKILL.md` 与 `references/`。

## 安装与使用

将本仓库放到 AI 助手的技能目录即可，例如：

- 用户级技能：`~/.workbuddy/skills/douziguo-skill/`
- 项目级技能：`<项目>/.workbuddy/skills/douziguo-skill/`

技能名由 `SKILL.md` 头部的 `name` 字段决定（当前为 `code-collab-rules`）。启用后，助手会在涉及源码改动的协作中自动遵循上述纪律。
